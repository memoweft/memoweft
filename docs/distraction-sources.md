# G9 第 6 项：干扰考点与确认来源

本项先核对冻结考试，再修复能通过真实形成流程复现的来源漏洞。历史
`false_memory_resistance = 0.5` **不证明有一半助手干扰被写成了用户事实**。
本次不重考、不修改原分数或标签，不声称这一指标已经提高。

## 冻结考试究竟计算了什么

依据停止考试的 `reports/valid-records.json`、`reports/reproduction-fixtures.json`、
`reports/qa-audit.json`，以及前 12 个完成会话的 `artifact.json`、缓存判词和来源链：

- `runner.summarize` 只取 `memory_source == interference` 的 16 条记录；
  8 条评分 0、6 条评分 1、2 条评分 2，指标为 `8 / 16 = 0.5`。
- `evaluation_for_memory_integrity` 接收的是每会话新增/变化的正式记忆正文，
  **没有调用问题召回，也没有使用给答题模型的 recall 渲染**。它把干扰命题
  当成普通 Expected Memory Point，按相关信息覆盖程度给 0/1/2 分。
  评分 1 可以只是主题相同、关键干扰信息缺失，甚至关键态度相反。
- 判词原件可以通过固定请求的 SHA-256 对照；本项语料保留原始英文、分数、
  缓存判词、每会话正文及冻结最终数据库的真实支持原话。数据库以只读方式打开，
  读取前后文件 SHA-256 相同，新增模型请求为 0。
- 7 个相关会话共有 156 条不同会话的新增/变化正文；来源关系均为 `stated`，
  并可核对用户原话。最终数据库可能带后续复述来源，因此这些最终来源链不能
  冒充每次考试时刻的独立快照。原会话正文和原判词仍单独保留。
- `reproduction-fixtures.json` 原来只有姓名和旅行检索夹具，没有这 16 条干扰评分。
  本项从完整记录补齐，不把问答中间名猜测归到本指标里。

完整逐题材料在 [固定语料](../py/tests/fixtures/distraction-exam.json)。`ssession_id`
是原报告从 0 开始的会话编号；下面使用从 1 开始的编号。中文是新合成对照，
不是历史考试原句。所选用户/助手片段可能来自不同原始轮次，测试是隔离机制重放，
不是整段历史会话或真实模型重跑。

## 独立复现并修复的形成漏洞

调查来源检查时，发现现有 `formed_by=confirmed` 会用“任意两字符重合”判断
用户是否确认助手。英文在去掉空格后再检查否定，也失去了单词边界。
这属于 **Core 形成编译器的确认来源检查**，不是召回排名或渲染问题。

真实 durable boundary（持久输入边界）→ World worker（形成执行器）→ SQLite
→ `recall_world_snapshot`，固定模型持续建议 `form + confirmed`，旧代码可以形成并召回：

- 用户 `I like tea.`，助手 `You live in Oslo.`：`li` 重合就导入居住地。
- 用户 `我喜欢茶。`，助手 `你喜欢咖啡。`：`喜欢` 重合就导入咖啡偏好。
- 用户 `No, I live in Lima.`，助手 `You live in Oslo.`：否认仍可导入错误地点。
- 裁选用户 `Yes, not Oslo.` 里的 `Yes`，或 `是的，不是咖啡。` 里的 `是的`，
  可以绕过整条回复的否认。
- `Yes, tea.` 被用来确认 `You enjoy team sports.`：字符片段不是完整的值。

这些是**新构造的确定性反例**，不声称原考试模型曾输出相同的 `confirmed`。

### 确定性规则

1. 导入助手命题必须有明示确认：保留现有 `_AFFIRM_RE` 的肯定短语白名单；
   或“肯定短语 + 分隔符 + 助手命题中的完整逐字值”，中文值前可有“就是/正是”。
   例如 `对，就是G6`、`Yes, jasmine tea.`；明确执行确认 `Yes, do that.` 与既有“就这么办”对应，继续接受。英文值忽略大小写，并检查 ASCII
   单词边界；`tea` 不能借 `team` 通过。不靠活动、职业、宠物等主题词猜语义。
2. 保留原 40 字符上限。确认切片和**完整用户回复**都须满足规则，裁选肯定词
   不能抹掉同条回复的否认。否定和问号检查使用仍有词边界的原回复，原话不改写。
3. 普通陈述、反义陈述、未确认建议不能用 `confirmed` 导入助手全文；模型可以
   用 `stated` 对用户自己明确表达的事实选择完整来源。规则不自动改类型或补事实。
4. `stated` 仍逐字派生用户命题。原来的重述关联检查仅关联其助手上下文，
   不导入助手的其他内容；本次严格规则只约束 `confirmed` 的内容导入。
5. 提示词同步解释新合同；不新增重试、等待或期限，不改变原有一次编译反馈改写。
   不改 SQLite 表结构、标签、原始 Evidence、召回打分或历史状态标记。

### 已知限制与保留行为

- 白名单之外的简略答法、无分隔符的“对就是G6”、`Yes, that's right`、长回复或
  混合多个事实的回复，可能不能走 `confirmed`。其中用户明确重述的事实交给
  模型以 `stated` 保留；没有用户陈述、又不满足明示确认规则时不导入助手命题。
  这是可解释的有限语法，不能宣称理解任意语言的确认语义。
- 裸肯定的标点沿既有规则处理，反问和反讽仍需模型解释。
- 裸 `Yes/是的` 是否确认了一个多命题建议、值与助手命题是否语义一致，仍需
  解释模型选择正确命题；本次不是通用反讽、假设、转述或多命题指代分类器。
- 不重算历史 0.5。删掉用户协作、创意、时间管理事实以提高它，会损害正确记忆。
  评测指标调整和真实模型复考由维护者另行决定。
- 固定历史中英文形成对照 16 条中，有 4 条在当前 main 的既有来源规则下不形成：
  `s4-i12` 中文“对我来说”触发其他说话人检查；`s5-i10` 中文被判任务内指令；
  `s10-i11` 英文复合句带否定意向；`s12-i7` 中文“想象力”触发目标白名单。
  语料逐条记录旧状态；本项未改这些规则，也未把它们说成成功形成或新增修复。
  另外 12 条维持形成及原话召回，所有 16 条 Evidence 保留。
